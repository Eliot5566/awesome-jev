# Ecosystem review: September 19, 2026

This review updates the [initial list at `9742866`](https://github.com/cobanov/awesome-jev/tree/9742866d7ba49071fa504d3c5cc08955f918e3ac), last committed September 18 at 10:16:51 UTC. The review crossed midnight in Europe/Istanbul; upstream dates in this note use UTC.

## Scope and method

- Searched GitHub repositories created since September 14 using both star-sorted and recently updated results: 379 unique discovery leads across two bounded queries, not an exhaustive ecosystem census.
- Used official TypeSafe documentation, provider announcements, and existing community directories to find gaps. Directory descriptions were leads, not evidence of implementation.
- Read 54 candidate READMEs and inspected relevant implementation files for the 52 entries added below. The table pins their README and source snapshots to commit IDs. A guide or DSL is identified as such rather than represented as a deployed application.
- Rechecked all 59 GitHub repositories linked in the initial README: all resolved, remained public, and were not archived at review time. This is an availability check, not a fresh behavioral audit of all existing entries.
- Added 52 community entries to the existing 50, for 102 community projects/resources. Official repositories, provider documentation, cookbooks, and related directories are counted separately.
- Ten additions were created after the initial list's final commit. The other 42 fill release-week omissions; an addition here does not imply that the project launched today. Creation time also does not establish when a project became usable.
- Review was read-only for upstream projects. No paid inference, browser/device automation, trading, third-party installation scripts, or benchmark reruns were performed. Runtime reliability, package installation, calibration, and security remain unverified by this list.

## First-party developments and corrections

**Python SDK 0.7.0:** the September 18 [release](https://github.com/typesafe-ai/typesafe-sdk-python/releases/tag/v0.7.0) replaces `msgspec` serialization with Pydantic, adds `response_model`, and fixes serialization of string subclasses. It predates the initial README commit but was missing from its update coverage. The [JavaScript changelog](https://docs.typesafe.ai/sdk/javascript/changelog) still identifies 0.6.0 as its latest documented release; Python and JavaScript versions should not be conflated.

**Provider coverage:** Vercel's September 16 [announcement](https://vercel.com/changelog/typesafe-ai-jev-now-available-on-ai-gateway) documents `typesafe-ai/jev` through the experimental AI SDK evaluation interface, including the Boolean primitive. [OpenRouter](https://openrouter.ai/typesafe/jev-1.13) lists `typesafe/jev-1.13` with a September 18 date. [Cloudflare](https://developers.cloudflare.com/ai/models/typesafe/jev/) documents `typesafe/jev` with state and typed questions. These are distinct integrations, not interchangeable model IDs or evidence of separate upstream model releases.

**Model and input limits:** [TypeSafe's model page](https://docs.typesafe.ai/models) currently resolves both stable and preview aliases to `jev-1.13.0`, with no separate preview build. Hosted Jev accepts text, including structured text state, not raw images, audio, or video. Its documented budgets are 64k tokens for the whole request and 32k for state plus the longest question. Provider catalogs displaying 32k do not establish that every route exposes the same total batching budget. Pin the model and verify the chosen provider's contract when reproducing results.

**Primitive semantics:** the original “yes/no/unknown-style” explanation was imprecise. [Noul](https://docs.typesafe.ai/primitives/noul) returns the probability of yes, with no separate confidence field. Choice and Score return a distribution and a derived [confidence](https://docs.typesafe.ai/confidence). An application decides whether to abstain or request review; an unknown state is not a third built-in Noul output.

**Failure modes:** the first-party [jaggedness guide](https://docs.typesafe.ai/model-jaggedness/jev-1.13) documents weaknesses in counting, arithmetic, date comparison, indirect questions, irrelevant context, and adversarial state. It also cautions against assuming complementary answers or equivalence between Choice and Noul formulations. The README now links this alongside the success-oriented material.

## What the new projects show

**Browser and device control:** Jev Ultrafast selects DOM operations and targets while a separate LLM supplies text. Mobile Jev acts through Mobilerun on a real Android device; its Uber recording reaches payment selection without demonstrating a completed booking. The Codex browser skill likewise separates navigation judgments from text entry and final verification. These are hybrid systems with explicit execution code, not evidence that hosted Jev gained vision or text generation.

**Context pruning:** Claude Code, Codex, and Pi now have distinct implementations. Their shared approach is to judge which history to retain, not regenerate a summary of everything. Retained text can remain exact while the selection is still wrong. Yoshi explicitly presents itself as a proof of concept; fast-dev-compaction is a Codex port, and the Pi implementations differ in how they preserve or filter session history. Host hook compatibility was not exercised here.

**Data and workflow integration:** DuckDB and PostgreSQL extensions, an n8n node, a LlamaIndex reranker/router, and additional Ruby, Java, R, and Haskell tooling broaden the integration surface. `jev-dsl` provides typed encoding/decoding rather than a network client. The tax classifier is a useful example of separating candidate selection from deterministic PDF processing, but its headline should not be read as universal accuracy: its README reports 38 low-confidence strict errors among 753 blank-form pages, and scanned pages require OCR. Jev Reviewer selects source quotes for research extraction; its output is not a clinical recommendation.

**Open models:** SemIf, NanoJev, kev, Jevlike, Jev Visual, reflex, Simple Jev, and the DiffusionGemma-based OpenJev take different approaches to finite-option inference. Some read pretrained logits; others train heads or adapters. Sharing an interface does not reproduce TypeSafe's architecture, RLCD, or calibration. Jev Visual specifically says its candidate probabilities are not correctness estimates. The DiffusionGemma server documents a patched vLLM dependency. NanoJev's game comparisons include shared controller/planning code.

**Evaluation:** the added studies examine classification calibration, prompt sensitivity, retrieval relevance, and tool routing. The 100 tools in `jev-eval-agent` are mocked. The retrieval study explicitly examines circularity from using a model as a judge of its own reranking. The behavior study uses synthetic tasks and repeated calls, not an overall intelligence score. No common speedup or accuracy figure is inferred across these incompatible setups.

**Action boundaries:** `jev-trader` includes a real order path. Its configuration defaults to a mock model and dry-runs without a private key; selecting the Jev model and enabling live execution are separate choices. Driving and drone entries describe simulations. Guard tools inspect actions but are not represented as proven security boundaries.

## Deferred candidate

[Jev Traffic Sim](https://github.com/skcache/jevtrafficsim) was discovered through repository search. Its README mentions a Jev controller, but the inspected snapshot exposed fixed/adaptive controllers and a placeholder `jev/` directory without an inspectable Jev decision path. It was not added on that description alone. This is a snapshot limitation, not a claim that future versions lack the integration.
